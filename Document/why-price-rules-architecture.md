# เหตุผลที่ไม่มีการคำนวณราคาลงในแท็บ "PRICE_RULES" (Database Architecture & Design Rationale)

เอกสารนี้อธิบายถึง **โครงสร้างทางสถาปัตยกรรมฐานข้อมูล (Database Architecture)** ว่าเหตุใดแท็บ **`PRICE_RULES`** จึงไม่มีการบันทึกผลการคำนวณราคา และผลลัพธ์การคำนวณราคาของแต่ละงานคำขอถูกจัดเก็บไว้ที่ใดในระบบ

---

## 1. ข้อแตกต่างระหว่าง Master Data กับ Transaction Data

ในระบบฐานข้อมูลมาตรฐาน (ERP, ระบบสั่งซื้อ, ระบบงานบริการ) ข้อมูลจะถูกแบ่งออกเป็น 2 ประเภทหลักที่มีบทบาทหน้าที่ต่างกันโดยสิ้นเชิง:

```
+-----------------------------------------------------------------------------+
|                         สถาปัตยกรรมการไหลของข้อมูลราคา                           |
+-----------------------------------------------------------------------------+
|                                                                             |
|  [ แท็บ PRICE_RULES ] (Master Data - ตารางมาสเตอร์ราคากลาง)                      |
|  - ถ่ายเอกสารขาวดำ: แผ่นละ 0.50 บาท                                           |
|  - พิมพ์ 2 หน้า สี: แผ่นละ 2.00 บาท                                            |
|  - นามบัตร: ใบละ 3.00 บาท                                                   |
|                                                                             |
|                                |                                            |
|                                | 1. ดึงอัตราต่อหน่วยมาคูณกับจำนวน                  |
|                                v                                            |
|                                                                             |
|  [ ระบบหน้าเว็บ / ฟอร์มสั่งพิมพ์ ]                                                |
|  คำนวณ: 10 แผ่น x 5 ชุด x 0.50 บาท = 25.00 บาท                                 |
|                                                                             |
|                                |                                            |
|                                | 2. บันทึกผลการคำนวณลงฐานข้อมูล                    |
|                                v                                            |
|                                                                             |
|  [ แท็บ JOB_ITEMS ] (Transaction Line Items)                                |
|  - job_no: PRN-202609-0001                                                  |
|  - quantity: 50 แผ่น                                                         |
|  - unit_price: 0.50 บาท (ราคาต่อหน่วย ณ วันสั่ง)                                 |
|  - estimated_amount: 25.00 บาท (ผลลัพธ์คำนวณระดับรายการ)                         |
|                                                                             |
|                                |                                            |
|                                | 3. สรุปยอดรวมใบคำขอ                           |
|                                v                                            |
|                                                                             |
|  [ แท็บ JOBS ] (Transaction Header)                                         |
|  - job_no: PRN-202609-0001                                                  |
|  - estimated_amount: 25.00 บาท (ยอดประเมินรวมทั้งงาน)                            |
|  - confirmed_amount: 25.00 บาท (ยอดยืนยันโดยแอดมิน)                             |
|                                                                             |
+-----------------------------------------------------------------------------+
```

### เปรียบเทียบหน้าที่ของแต่ละแท็บ:

| คุณสมบัติ | แท็บ `PRICE_RULES` (Master) | แท็บ `JOB_ITEMS` & `JOBS` (Transaction) |
|---|---|---|
| **บทบาทหลัก** | **แคตตาล็อกราคากลาง** (Rate Card / Price Master) | **ประวัติคำขอพิมพ์จริง** (Order History) |
| **หน้าที่** | เก็บ "กฎเกณฑ์และราคาต่อหน่วย" เท่านั้น | เก็บ "จำนวน, รายการที่สั่ง, และผลคูณยอดเงินรวม" |
| **ความถี่ในการเพิ่มข้อมูล** | เพิ่ม/แก้ไขเฉพาะเมื่อโรงพิมพ์ปรับราคากลาง (แถวคงที่) | เพิ่มแถวใหม่ทุกครั้งที่มีผู้ใช้ยื่นคำขอพิมพ์งาน |
| **ตัวอย่างข้อมูล** | `copy`: A4 ปอนด์ 70 แกรม ขาวดำ = **0.50 บาท/แผ่น** | `PRN-0001`: สั่ง 500 แผ่น = **250.00 บาท** |

## 2. เหตุผลสำคัญ 4 ประการที่ไม่บันทึกผลการคำนวณลงใน `PRICE_RULES`

### 1) ป้องกันประวัติและรายงานย้อนหลังในอดีตเสียหาย (Historical Integrity)
* **ปัญหาที่จะเกิดขึ้นหากคำนวณในตารางราคา:**
  สมมุติว่าวันนี้ ค่าถ่ายเอกสารแผ่นละ `0.50 บาท` มีการสั่งงาน 1,000 แผ่น เป็นเงิน `500 บาท` หากในอีก 6 เดือนข้างหน้า มหาวิทยาลัยปรับราคาขึ้นเป็น `0.70 บาท` แล้วไปแก้ไขตัวเลขในตารางราคา ผลการคำนวณยอดเงินของงานเก่าทั้งหมดในอดีตจะกลายเป็น `700 บาท` ทันที ทำให้รายงานสรุปงบการเงินย้อนหลังผิดพลาดทั้งหมด
* **วิธีแก้ของระบบ:**
  ระบบจึงแยกมาเก็บผลการคำนวณและราคา ณ วันสั่งลงในแท็บ `JOB_ITEMS` พร้อมเก็บ **`price_rule_snapshot`** ไว้ ทำให้รายงานในอดีตถูกต้องถาวร ไม่ว่าจะมีการปรับราคากลางใหม่กี่ครั้ง

### 2) กฎความเป็นมาตรฐานของฐานข้อมูล (Database Normalization)
* ตามหลักสถาปัตยกรรมซอฟต์แวร์ ตารางราคากลางจะต้องเป็น **Single Source of Truth** ที่มีเฉพาะอัตราอ้างอิง
* ตาราง `PRICE_RULES` ไม่มีคอลัมน์เลขที่งาน (`job_no`) หรือจำนวนที่สั่ง (`quantity`) เพราะตารางนี้ไม่ได้ผูกกับบุคคลใดบุคคลหนึ่ง แต่เป็นราคากลางสำหรับทั้งมหาวิทยาลัย

### 3) รองรับบริการที่มีช่วงราคาและต้องประเมินหน้างาน (Variable Pricing)
* งานพิมพ์บางประเภทไม่ได้มีสูตรคูณตายตัว เช่น:
  * **งานออกแบบ/จัดรูปเล่ม (`layout`):** มีช่วงราคา `100 – 200 บาท/หน้า` ขึ้นอยู่กับความยากง่ายของ Artwork
  * **งานเข้าเล่ม (`bind`):** เป็น `MANUAL_QUOTE` แอดมินต้องดูความหนาของเล่มก่อนประเมินราคา
* ผลลัพธ์ราคาสุดท้ายจึงต้องถูกบันทึกและยืนยันในระดับคำขอ (`confirmed_amount` ใน `JOBS` และ `JOB_ITEMS`)

### 4) ความเป็นอิสระของข้อมูล (Data Independence)
* แอดมินโรงพิมพ์สามารถเข้ามาเปิด/ปิดใช้งาน (`active / inactive`) หรือแก้ไขราคาโปรโมชันในแท็บ `PRICE_RULES` ได้ตลอดเวลา โดยไม่กระทบกับข้อมูลคำขอที่กำลังดำเนินการอยู่ในปัจจุบัน

## 3. สรุปจุดที่เก็บผลลัพธ์การคำนวณราคาใน Google Sheet

เมื่อมีคำขอพิมพ์งานเกิดขึ้น ผลลัพธ์การคำนวณจะถูกบันทึกใน **2 แท็บ** ดังนี้:

1. **แท็บ `JOB_ITEMS` (ผลคำนวณรายชิ้นงาน):**
   * คอลัมน์ E: `quantity` (จำนวนที่สั่ง)
   * คอลัมน์ G: `unit_price` (ราคาต่อหน่วยที่ดึงมาจาก `PRICE_RULES`)
   * คอลัมน์ H: `estimated_amount` (ยอดเงินรวมของรายการนี้ = `quantity × unit_price`)
   * คอลัมน์ I: `confirmed_amount` (ยอดยืนยันโดยเจ้าหน้าที่)

2. **แท็บ `JOBS` (ผลคำนวณยอดรวมทั้งใบงาน):**
   * คอลัมน์ K: `estimated_amount` (ราคารวมประเมินเบื้องต้นของงาน)
   * คอลัมน์ L: `confirmed_amount` (ราคารวมสุทธิที่แอดมินยืนยันให้เรียกเก็บเงิน)

## 4. ข้อแนะนำในการต่อยอดระบบ (Auto-Calculation Enhancement)

หากต้องการให้ทุกครั้งที่ผู้ใช้ส่งคำขอผ่านหน้าเว็บ มีการคำนวณและหยอดตัวเลข `estimated_amount` ลงในแท็บ `JOBS` และ `JOB_ITEMS` ทันทีโดยอัตโนมัติ (ไม่ให้ช่องว่าง):
* สามารถปรับฟังก์ชัน `doSubmitJob` ในหน้าเว็บ ให้ดึงราคาจาก `PRICE_RULES` มาคูณกับจำนวนชุด/แผ่น แล้วส่งค่ายอดเงิน `estimatedAmount` ไปบันทึกลง Google Sheet พร้อมกับคำขอได้ทันทีครับ
