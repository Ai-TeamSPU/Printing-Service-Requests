# เชื่อมต่อ Google Sheet + Google Drive จริง (Google Apps Script)

เว็บ Printing-Service-Requests ใช้ **Authentication Gateway** ตรวจ Google Workspace ก่อนส่งคำขอไปยัง Google Apps Script ซึ่งทำหน้าที่อ่าน/เขียน Sheet และ Drive หน้าเว็บจะไม่ถือ Apps Script URL, `CONNECT_TOKEN`, Spreadsheet ID หรือ Folder ID อีกต่อไป ดูขั้นตอน Gateway ที่ [`auth-gateway/README.md`](../auth-gateway/README.md)

> **Security cutover:** ห้ามใช้วิธีเดิมที่ฝัง `CONNECT_TOKEN` ไว้ในหน้าเว็บ เพราะ token ที่อยู่ใน browser ไม่ใช่การยืนยันตัวตน หลังอัปเดต `Code.gs` ทุก user-facing action ต้องมี `AUTH_GATEWAY_TOKEN` จาก Gateway และ actor ที่ตรวจสอบแล้ว

> **Google Authentication:** เพิ่มคอลัมน์ `requester_google_sub` ต่อท้ายแท็บ `JOBS` เพื่อใช้ Google `sub` เป็นรหัสเจ้าของงานแบบถาวร งานเก่าที่ยังไม่มีค่านี้จะ fallback ไปเทียบ verified email ชั่วคราว หลังวางโค้ดใหม่ต้องรัน `setupSheets()` หนึ่งครั้ง

> **อัปเดตล่าสุด:** เพิ่มคอลัมน์ `budget_source` และ `budget_acct` ต่อท้ายแท็บ `JOBS` (ใช้คำนวณ "สรุปรายได้" ในเอกสารสรุปรายงานจากแหล่งงบประมาณจริงที่ผู้ขอเลือก แทนสัดส่วนสมมติ) — ถ้าตั้งค่าไว้แล้วก่อนหน้านี้ ต้อง **วางโค้ด `Code.gs` เวอร์ชันใหม่ทับของเดิม แล้วรัน `setupSheets` อีกครั้ง** เพื่อเพิ่ม 2 คอลัมน์นี้ให้ชีตที่มีอยู่ (ข้อมูลแถวเดิมจะไม่หายหรือถูกแก้ไข) จากนั้น Deploy เวอร์ชันใหม่ตามขั้นตอนที่ 7
>
> **อัปเดตอีกรอบ:** ปุ่ม "ส่งอีเมล" ในหน้า "เอกสารสรุปรายงาน" ตอนนี้ส่งอีเมลจริงผ่าน `MailApp` แล้ว (ต้องกรอกอีเมลปลายทางในกล่องที่เด้งขึ้นมาทุกครั้งก่อนส่ง ไม่มีอีเมลตายตัว) — วางโค้ด `Code.gs` เวอร์ชันใหม่ทับแล้ว **Deploy เวอร์ชันใหม่** ตามขั้นตอนที่ 7 อีกครั้ง ไม่ต้องรัน `setupSheets` เพิ่มสำหรับส่วนนี้ (ไม่มีการเพิ่มคอลัมน์) แต่ครั้งแรกที่กดส่งอีเมลอาจมีป๊อปอัปขอสิทธิ์ "ส่งอีเมลในนามของคุณ" (Gmail scope) — ต้องไปกด **Allow** เองในตัวแก้ไข Apps Script ก่อน โดยเลือกฟังก์ชัน `authorizeMailSend` จาก dropdown แล้วกด Run ครั้งเดียว (ดูหัวข้อ "ส่งอีเมลรายงานให้ผู้บริหาร" ด้านล่าง)
>
> **อัปเดตอีกรอบ:** เพิ่มการตรวจจับอีเมลผู้ขอกับ "ทะเบียนบุคลากร" — ตอนกรอกอีเมล @spu.ac.th ที่หน้า gate ("เริ่มใช้บริการ") ระบบจะเทียบกับแท็บ **`Personnel_Information`** ถ้าเจอ จะดึงชื่อ-สกุลและหน่วยงานมาเติมฟอร์มให้อัตโนมัติ — วางโค้ด `Code.gs` เวอร์ชันใหม่ทับแล้ว **Deploy เวอร์ชันใหม่** ตามขั้นตอนที่ 7 จากนั้นดูหัวข้อ "ทะเบียนบุคลากร (Personnel_Information)" ด้านล่างเพื่อสร้างแท็บนี้
>
> **อัปเดตอีกรอบ:** แยกคอลัมน์ `variant_snapshot` ในแท็บ `JOB_ITEMS` ออกเป็นคอลัมน์ย่อย `color_mode, paper_size, paper_type, sides, staple, own_paper, qty_original, qty_sets, exam_type, exam_subject` (คอลัมน์ M-V) เพื่อให้เปิดชีตแล้วเห็นรายละเอียดแยกเป็นคอลัมน์ชัดเจน — **เลิกเขียนคอลัมน์ `variant_snapshot` (D) สำหรับงานใหม่แล้ว แต่คอลัมน์เดิมยังอยู่ ไม่ได้ลบ** ข้อความสรุปของงานเก่าที่เคยบันทึกไว้ก่อนหน้านี้จึงไม่หาย — วางโค้ด `Code.gs` เวอร์ชันใหม่ทับ แล้ว **รัน `setupSheets` อีกครั้ง** เพื่อเพิ่มคอลัมน์ M-V ให้ชีตที่มีอยู่ (ข้อมูลเดิมไม่หาย) จากนั้น Deploy เวอร์ชันใหม่ตามขั้นตอนที่ 7
>
> **อัปเดตอีกรอบ:** ต่อระบบคำนวณราคาประมาณการอัตโนมัติสำหรับบริการ `copy`/`dup`/`exam` เข้ากับ `doSubmitJob` แล้ว (เขียน `unit_price`/`estimated_amount` ให้จริง) — เป็นการแก้ที่ฝั่งหน้าเว็บ (`index.html`) ล้วน ๆ **ไม่ต้อง deploy Apps Script ใหม่สำหรับส่วนนี้** รายละเอียด/ข้อจำกัดดู [Document/why-price-rules-architecture.md](../Document/why-price-rules-architecture.md) ข้อ 4
>
> **อัปเดตอีกรอบ:** หน้า "ตารางราคา" เชื่อมต่อแท็บ `PRICE_RULES` จริงแล้ว (อ่าน + สลับเปิด/ปิดกฎราคา) — วางโค้ด `Code.gs` เวอร์ชันใหม่ทับแล้วรันฟังก์ชัน **`seedPriceRules`** ครั้งเดียว (ใส่ราคาตั้งต้นให้ถ้าแท็บยังว่างอยู่ ไม่แตะถ้ามีข้อมูลแล้ว) จากนั้น Deploy เวอร์ชันใหม่ตามขั้นตอนที่ 7 — **หมายเหตุ:** ตัวคำนวณราคาตอนส่งคำขอ (`computeItemPrice`) ยังไม่ได้อ่านจากแท็บนี้ แก้ราคาที่หน้า "ตารางราคา" จึงยังไม่มีผลต่อราคาที่คำนวณให้ผู้ขอเห็น
>
> **อัปเดตล่าสุด:** เพิ่มคอลัมน์ `service_group` ต่อท้าย `JOB_ITEMS` (คอลัมน์ W) เก็บว่ารายการนั้นมาจากกลุ่ม "งานผลิต" หรือ "งานพิมพ์และออกแบบ" — วางโค้ด `Code.gs` เวอร์ชันใหม่ทับ แล้ว **รัน `setupSheets` อีกครั้ง** เพื่อเพิ่มคอลัมน์นี้ให้ชีตที่มีอยู่ (ข้อมูลเดิมไม่หาย) จากนั้น Deploy เวอร์ชันใหม่ตามขั้นตอนที่ 7
>
> **อัปเดตระบบแชต:** เพิ่มแท็บ `JOB_MESSAGES` และ `CHAT_READS` สำหรับบทสนทนาประจำเลขที่งาน (`job_no`) พร้อมเพิ่มคอลัมน์ `client_upload_id` ต่อท้ายแท็บ `FILES` — หลังวาง `Code.gs` เวอร์ชันใหม่ ต้อง **รัน `setupSheets` อีกครั้ง** เพื่อสร้างสองแท็บและเพิ่มคอลัมน์นี้ แล้ว Deploy เวอร์ชันใหม่ตามขั้นตอนที่ 7 ข้อความใช้เวลา/UUID จากเซิร์ฟเวอร์ รองรับ retry แบบไม่สร้างข้อความซ้ำด้วย `clientMessageId` และไฟล์แชตหมวด `chat-attachments` จำกัด 5 ไฟล์ต่อข้อความ (ไม่เกิน 2 MB ต่อไฟล์) ระบบเพิ่มสิทธิ์ Viewer ของไฟล์ให้ผู้ขอ ผู้อัปโหลด และเจ้าหน้าที่ที่ active แบบ best-effort โดยไม่เปิดไฟล์เป็นสาธารณะ; ถ้านโยบาย Drive ไม่อนุญาต การอัปโหลดยังสำเร็จแต่ response จะมี warning

## ขั้นตอนติดตั้ง (ทำครั้งเดียว)

### 1. สร้าง Google Sheet
สร้างสเปรดชีตเปล่า 1 ไฟล์ ตั้งชื่อ เช่น `SPU-Printing-Service-DB`

### 2. วางสคริปต์
ในสเปรดชีตนั้น เปิด **ส่วนขยาย (Extensions) > Apps Script** แล้วลบโค้ดตัวอย่างเดิมทั้งหมด วางเนื้อหาไฟล์ [`Code.gs`](./Code.gs) ในโฟลเดอร์นี้แทน แล้วบันทึก (Ctrl+S)

### 3. ตั้งค่า Script Properties ฝั่งเซิร์ฟเวอร์
คลิกไอคอนรูปเฟือง **Project Settings** ทางซ้าย เลื่อนไปที่ **Script properties** กด **Add script property**

- `CONNECT_TOKEN`: รหัสสุ่มใหม่สำหรับ Gateway เรียก Apps Script
- `AUTH_GATEWAY_TOKEN`: รหัสสุ่มอีกค่าหนึ่ง ต้องไม่ซ้ำกับ `CONNECT_TOKEN`
- `SPREADSHEET_ID`: ID ของ Google Sheet
- `FOLDER_ID`: ID โฟลเดอร์แม่บน Drive

เก็บค่าทั้งหมดไว้ฝั่งเซิร์ฟเวอร์เท่านั้น ห้ามกรอกหรือฝังในหน้าเว็บ

### 4. สร้างแท็บทั้งหมดอัตโนมัติ
กลับไปที่ตัวแก้ไข เลือกฟังก์ชัน `setupSheets` จาก dropdown ด้านบน แล้วกด **Run** (รูปสามเหลี่ยม ▷)
- ครั้งแรกจะขึ้นขอสิทธิ์ (Authorize) — เลือกบัญชี Google ของคุณ แล้วกด **Advanced > Go to (ชื่อโปรเจกต์) (unsafe) > Allow** (ข้อความ "unsafe" เป็นเรื่องปกติสำหรับสคริปต์ที่คุณเขียนเอง)
- เมื่อรันเสร็จ กลับไปที่สเปรดชีต จะเห็นแท็บ `JOBS, JOB_ITEMS, PRICE_RULES, UNITS, USERS, FILES, STATUS_LOG, JOB_MESSAGES, CHAT_READS, NOTIFY_LOG, SETTINGS` พร้อมหัวตารางครบ

### 5. คัดลอก Spreadsheet ID
ดูที่ URL ของสเปรดชีต:
`https://docs.google.com/spreadsheets/d/`**`ตรงนี้คือ Spreadsheet ID`**`/edit`

### 6. สร้างโฟลเดอร์ Drive
สร้างโฟลเดอร์บน Google Drive ชื่อ เช่น `Printing-Service` (แนะนำสร้างเป็น Shared Drive ถ้าองค์กรมีสิทธิ์ใช้ เพื่อไม่ให้ไฟล์ผูกกับบัญชีคนเดียว) คัดลอก Folder ID จาก URL:
`https://drive.google.com/drive/folders/`**`ตรงนี้คือ Folder ID`**

### 7. Deploy เป็น Web App
กลับไปที่ตัวแก้ไข Apps Script กด **Deploy > New deployment**
- ไอคอนรูปเฟือง เลือกประเภท **Web app**
- Execute as: **Me**
- Who has access: **Anyone**
- กด **Deploy** แล้วกด **Authorize access** ถ้ามีขอเพิ่ม
- คัดลอก **Web app URL** (ลงท้ายด้วย `/exec`) เก็บไว้

### 8. ตั้ง Authentication Gateway

นำ Web App URL และ token ทั้งสองไปตั้งเป็น environment secrets ของ Gateway ตาม [`auth-gateway/.env.example`](../auth-gateway/.env.example) จากนั้นตั้ง `auth-config.js` ให้ชี้ URL ของ Gateway หรือใช้ reverse proxy แบบ same-origin แล้วจึงกด **ทดสอบการเชื่อมต่อทั้งหมด** ในหน้าแอดมิน

## ทะเบียนบุคลากร (Personnel_Information) — เติมฟอร์มอัตโนมัติตอนกรอกอีเมล

หลัง Google ยืนยันบัญชี @spu.ac.th แล้ว Gateway จะนำอีเมลที่ยืนยันแล้วไปเทียบกับแท็บ `Personnel_Information` — ถ้าเจอ จะดึง **ชื่อ-สกุล** และ **หน่วยงาน** มาเติมในฟอร์มให้อัตโนมัติ ผู้ใช้ไม่สามารถพิมพ์อีเมลผู้อื่นเพื่อสวมสิทธิ์ได้

**วิธีตั้งค่า:**
1. ในตัวแก้ไข Apps Script เลือกฟังก์ชัน **`setupPersonnelSheet`** จาก drop down แล้วกด Run — จะสร้างแท็บ `Personnel_Information` เปล่าพร้อมหัวตาราง `requester_email, full_name, unit_name` ให้ (ฟังก์ชันนี้ **จะไม่ทำอะไรเลยถ้าแท็บนี้มีอยู่แล้ว** ปลอดภัยกับข้อมูลเดิมของคุณ ต่อให้หัวตารางของคุณจะตั้งชื่อไม่เหมือนกันก็ตาม)
2. กรอกรายชื่อบุคลากรลงไป: คอลัมน์อีเมล, ชื่อ-สกุล, หน่วยงาน คนละแถว
3. ถ้าคุณมีแท็บนี้อยู่แล้วด้วยหัวตารางเป็นภาษาไทย (เช่น "ชื่อ-สกุล", "หน่วยงาน") ไม่ต้องแก้อะไร — ระบบรองรับหัวตารางได้ทั้งแบบอังกฤษ (`full_name`, `unit_name`, `email`) และแบบไทยอยู่แล้ว
4. ไม่พบอีเมลในทะเบียน หรือยังไม่ได้สร้างแท็บนี้ → ฟอร์มจะว่างให้กรอกเองตามปกติ ไม่มี error ใด ๆ ขึ้นให้ผู้ใช้เห็น

## ส่งอีเมลรายงานให้ผู้บริหาร — อนุมัติสิทธิ์ครั้งแรก

ปุ่ม "ส่งอีเมล" ในหน้า "เอกสารสรุปรายงาน" ต้องขอสิทธิ์ Gmail scope เพิ่มจาก Apps Script ก่อนถึงจะใช้ได้ (ครั้งเดียวพอ):
1. ในตัวแก้ไข Apps Script เลือกฟังก์ชัน **`authorizeMailSend`** จาก dropdown แล้วกด Run
2. จะมีหน้าต่าง "Authorization required" เด้งขึ้น → Review permissions → เลือกบัญชี (ต้องเป็นบัญชีเดียวกับที่ deploy Web App) → Advanced → Go to [ชื่อโปรเจกต์] (unsafe) → Allow
3. เช็คอินบ็อกซ์ของบัญชีนั้น ควรได้รับอีเมลทดสอบ "ทดสอบสิทธิ์ส่งอีเมล — SPU Printing Service"
4. ไม่ต้อง Deploy เวอร์ชันใหม่หลังจากนี้ สิทธิ์ผูกกับโปรเจกต์ ทำครั้งเดียวจบ

## ข้อควรรู้

- **ตอนนี้ใช้เฉพาะ Google Sheet ก็พอ** — ถ้ายังไม่ตั้ง `FOLDER_ID` ใน Script Properties ระบบจะบันทึก `JOBS` และ `JOB_ITEMS` ได้ตามปกติและข้ามการสร้างโฟลเดอร์ Drive โดยคอลัมน์ `drive_folder_id` จะว่าง
- ก่อนส่งคำขอ ผู้รับบริการต้องมี Google session ที่ Gateway ยืนยันแล้ว หน้าเว็บจะไม่เก็บ ID token หรือ session token ใน `localStorage`
- Apps Script URL, token, Spreadsheet ID และ Folder ID อยู่ฝั่งเซิร์ฟเวอร์เท่านั้น หน้าเว็บไม่มีช่องแก้ค่าเหล่านี้
- **หน้าคิวงาน / งานของฉัน / แดชบอร์ด / ติดตามสถานะ / ข้อมูลการคำขอรับบริการ** ดึงข้อมูลจริงจาก Google Sheet ทั้งหมดแล้ว (ไม่มีข้อมูลตัวอย่าง/mock ปนอยู่อีกต่อไป) — ถ้ายังไม่ได้ตั้งค่าเชื่อมต่อ หน้าต่าง ๆ จะแสดง "ไม่มีข้อมูล" แทนที่จะมีตัวอย่างให้ดูเฉย ๆ
- Web App สามารถตั้ง "Who has access: Anyone" เพื่อให้ Gateway เรียกได้ แต่ browser ต้องไม่เรียก Apps Script โดยตรง ความปลอดภัยมาจาก Google session, role policy และ token ฝั่งเซิร์ฟเวอร์สองชั้น ไม่ใช่ `CONNECT_TOKEN` ใน browser
- ถ้าแก้โค้ดใน `Code.gs` ภายหลัง ต้องทำ **Deploy > Manage deployments > แก้ไข (ไอคอนดินสอ) > Version: New version > Deploy** ใหม่ทุกครั้ง ไม่งั้น URL เดิมจะยังรันโค้ดเวอร์ชันเก่าอยู่
